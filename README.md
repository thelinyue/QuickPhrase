# 闪语 QuickPhrase

Windows 10（1607+）／11 x64 本地话术工具，使用 Tauri 2、Rust、React／TypeScript。界面和名称已于 2026-10-10 确认，当前版本为 0.2.0。

正式下载：[v0.2.0 发布说明与校验清单](https://github.com/thelinyue/QuickPhrase/releases/tag/v0.2.0) · [Windows x64 安装器](https://github.com/thelinyue/QuickPhrase/releases/download/v0.2.0/Shanyu-Setup-0.2.0-x64.exe) · [便携 ZIP](https://github.com/thelinyue/QuickPhrase/releases/download/v0.2.0/Shanyu-0.2.0-win-x64.zip)。安装器和程序未代码签名；[Hub 公开镜像](https://github.com/users/thelinyue/packages/container/package/quickphrase-hub)及[可复制的 Compose 部署配置](docs/team-sharing.md)已提供。

当前源码为尚未发布的0.2.1，统一英文名称 QuickPhrase。0.2.0的下载链接与文件保持原名；新名称将在后续发布中提供。

## 使用

1. 聚焦目标输入区，再打开闪语。
2. 单击选中话术；双击正文将内容添加到当前输入位置。
3. 默认点击左侧黄色发送按钮，或右键选择“直接发送”才发送。可在常用设置主动将话术双击、常用短语单击改为直接发送；已有草稿会保留，发送作用于输入区的最终内容。

支持分类、折叠分组、排序、移动／复制、标题配色、自定义快捷键、搜索、文字／图片／文件与分段。独立文件库只关联源文件，失效记录可重新关联，删除关联不会删除原文件。

每个人使用普通账号登录，管理“我的话术”，需要共享时通过“共享库 ▾”加入已授权的库。服务管理员维护账号与公共资源；库内角色为查看者、编辑者、库管理员，创建共享库默认需授权。账号昵称及联系方式可选，已有用户名、名称和内容保持原样。主菜单提供“账号与同步、共享库管理、云文件”，服务管理员另有“账号管理”。

云文件是这台 Hub 的公共文件库，完成初始改密的用户无需加入共享库即可查看、下载和使用。上传、删除、恢复分别按账号授权；删除会移入回收站，配置权限和永久删除仅服务管理员执行。保留纯图标操作、文件系统图标、分页、传输管理和回收站；共享库直接引用云文件，我的话术保存独立副本，下载完成不自动投递。

个人同步默认关闭，在“账号与同步”预览合并后开启；我的话术、回收站、素材、常用短语及个人偏好按账号同步。退出后可继续离线编辑，同账号登录再同步，切换账号不自动带入内容。共享库缓存支持断网及离线重启使用，离线只读；退出清理共享库缓存。说明及恢复规则见 [账号与同步](docs/private-sync.md)。

话术正文使用连续图文编辑区，图片在当前光标或选区位置插入，保留前后文字与分段顺序。工具栏仅有日期、图片、文件和添加分段；每条最多9张图片、9个文件。包含图片的话术在列表及搜索结果显示图片图标，移除全部图片并保存后恢复普通话术图标。

删除话术、一级／二级话术分类时，确认窗口默认勾选“移除到回收站”；取消勾选后永久删除。底部主菜单可打开回收站，支持关键词、全拼、首字母搜索和分页，显示原分类、正文、图片及附件。还原恢复原内容与分类；二级分类后来被移动时，在原位置重建所需分组，保留已移动的活动内容。快捷键冲突时保留回收记录，可明确选择不恢复快捷键后重试。文件关联和独立常用短语不进入回收站。

本地文件右键支持复制文件、修改显示名、移除关联、快速排序、移动分类、打开文件／所在位置、重新关联和刷新状态。Ctrl 单击多选、Shift 连续选择、Ctrl+A 选择当前分类；复制、移动和移除支持批量操作。文件分类支持新增、重命名、删除和快速排序。显示名修改及分类移动均不改变源文件。

首次使用不预建话术或文件分类，点击“新增一级分类”自行创建，再添加话术或关联文件。允许删除全部分类，重启后保持为空；已有分类不会因升级自动删除。一级分类和二级分类名称允许重复，各分类独立保存；分类选择框和快速排序显示同名序号，主界面标签保留原名称。话术行鼠标悬停为米黄色，单击选中为淡黄色，移出鼠标后恢复选中色。

在话术正文上停留350毫秒后，按参考图在真实鼠标位置右下方显示300像素宽的轻量预览，间距12像素。白底细边框，只显示标题、快捷键和正文，不使用独立标题栏、关闭按钮、底部提示和窗口阴影。固定展开方向，屏幕边缘也不翻转或反向平移，超出屏幕的部分会被裁切。预览保留换行、图文、文件名及分段，短文按内容收紧高度，长文可进入浮层滚动查看。快速掠过或悬停发送按钮不弹出正文；移开鼠标、点击、列表滚动和Esc关闭预览，切换话术从正文开头阅读。预览窗口不激活，不改变原输入目标，主列表、主窗口搜索和底部搜索复用相同交互。

常用短语独立维护，每条为不超过 16 字的单行文字。点击“＋”新增，右键可修改、删除或打开快速排序窗口；排序支持 Ctrl 多选拖动，取消不保存，确定后两处短语栏同步更新。默认单击选中、双击插入；单击可配置为插入或直接发送，配置后双击不重复提交。左右键选择相邻项，上下键选择相邻行中最近的项，Enter 直接发送；主窗口和底部短语栏使用相同行为。

主窗口右上依次为吸附、置顶和最小化。底部按钮可分别显示／隐藏常用短语和搜索框，设置自动保存。普通启动和开机启动默认驻留托盘，开启吸附后随已识别的企业微信主窗口或独立聊天窗口无激活地显示，不抢焦点；重复运行不主动唤起。主窗口、底栏和正文预览不占任务栏，主动打开的设置和编辑窗口保留任务栏入口。目标最小化、关闭或切换其他程序时侧栏与底栏一起隐藏，返回目标后恢复；使用闪语及其设置、编辑窗口时保持跟随。手动隐藏持续到再次唤起。没有可用目标时可用托盘或快捷键独立打开，有效目标重新激活后恢复吸附；关闭左右吸附恢复原独立位置和尺寸。隐藏搜索后按 Alt+Q 会展开并聚焦；Alt+E 会显示并聚焦常用短语。

自动吸附按 `WXWork.exe` 和精确窗口类型识别主窗口及独立聊天窗口，不依赖 UI Automation 输入框，也不要求输入焦点。主窗口内切到通讯录或搜索时继续吸附；登录、独立图片／视频、搜索结果及未知类型窗口不吸附。侧栏与底栏共用目标，不向同进程的其他窗口继承吸附关系。v0.1.3 修复了 v0.1.2 拒绝真实企业微信吸附的缺陷；具体实机验证范围见验收记录。

底部短语栏的可见左右边缘与目标窗口对齐，侧栏紧贴目标可见边缘；闪语自身不可见边框按当前窗口动态补偿。底部“隐藏短语”关闭整个短语栏，菜单及新增按钮一起隐藏；可在“设置→界面设置→显示底部吸附常用短语”重新打开。底部搜索若已开启会独立保留。

侧栏移动、缩放和闲置时始终完整展开，旧“吸附时自动隐藏”“贴边显示防误触”选项已移除，旧库对应设置仍可读取。用户宽度按逻辑像素保存、按侧栏自身DPI换算，底栏内容高度按底栏自身DPI换算，跟随定位与屏幕裁剪不覆盖宽度。侧栏跟随目标可见顶部与高度，底栏跟随底边，目标部分移出屏幕时按显示器工作区裁剪。原吸附侧空间不足时，保持设置的侧边在屏幕内完整显示，必要时覆盖目标边缘。激活目标时同步侧栏层级，避免被其他普通窗口遮挡；普通目标保持普通窗口层，目标置顶时跟随置顶，关闭吸附后恢复用户置顶设置。

吸附图标开口朝左，关闭吸附时带左下至右上的斜线，开启时显示普通磁铁。置顶图标开启时实心、关闭时空心；常用短语和搜索框显示时为睁眼图标、隐藏时为斜线眼图标。这四个开关只通过图标区分状态，不叠加开启态浅色底块。界面使用直角，Windows 11 的客户端窗口外框也禁用系统圆角。

一级分类右键与右上角入口共用参考图的11项菜单，第二项为“新增二级分类”，归属菜单所指向的一级分类；“新增同级分类”新建一级分类。菜单使用直角灰底、32像素行高；二级分类保留自己的操作菜单。话术列表空白右键提供“新增话术”和“新增二级分类”，归属当前一级分类；文件列表空白右键仍为“刷新”。底部保留应用菜单。分类复制／移动的目标为其他一级分类，同名二级分组合并，内容追加到目标末尾。移动保留快捷键并移除来源分类，复制清空副本快捷键。“删除一级分类但保留话术”位于底部主菜单，话术移至明确选择的目标并取消分组；二级分类的保留删除仍位于其右键菜单，话术归入原一级分类。

一级分类标签可分别选择十二色色板或恢复默认颜色。菜单中的“设置一级分类背景色”打开设置页的“界面设置”，预选所点击的分类；已有设置窗口也会切换页面与分类。一级分类栏高度默认31像素，可设为31—200像素，增加高度后标签换行。界面设置提供标题和内容、仅标题、仅内容三种显示模式，以及默认展开／收起二级分类。

界面设置提供七种主题、10—18像素话术字体、标题默认色、我的话术／文件分类默认背景色、话术／文件标签顺序、窗口自由调整及吸附状态记忆。单个分类配色优先于默认色，单条话术独立颜色优先于标题默认色；旧版默认橙色会跟随全局默认色。话术／文件分类区域分别设置31—200像素，侧边短语区域最大高度28—300像素；底部短语可限制为一、二、三行或自适应，超出内容可以滚动。关闭吸附状态记忆后，当前会话可继续吸附，下次启动驻留后台，由托盘或快捷键唤起独立窗口。

主窗口保持窄侧栏，标题栏和底栏双击不最大化，避免与吸附定位冲突后显示空白。单击拖动、自由调整和最小化照常；独立排序窗口仍可最大化／还原。

底部吸附搜索栏共用本地搜索服务和话术行，支持匹配方式、高亮、上下选择、Enter插入、Esc关闭、悬停按钮和右键直接发送。“搜索结果使用后”设置作用于主窗口与底部搜索。

编辑器工具栏仅含日期、图片、文件和添加分段。新增与编辑话术的正文均支持粘贴剪贴板图片，图片插入原选区和分段，保存为本地素材。标题最多 200 字，正文总计最多 5000 字，每条最多 9 张图片、9 个文件。图片导入为静态 PNG；GIF 当前保存首帧，动图原文件可以作为文件关联。颜色选择使用居中矢量勾，各窗口标题栏使用软件图标。点击空白或切换话术与短语区域会取消旧选中状态，恢复普通背景。

主窗口、底栏、预览及所有动态窗口均在WebView2层关闭通用表单自动填充，编辑、搜索、设置等输入场景不再显示“保存的信息”建议弹窗。

默认发送键 Enter，可切换 Ctrl+Enter；分段间隔默认 500 毫秒，可调整。Alt+Q 聚焦搜索，上下选择、Enter 插入、Esc 退出；Alt+W 显示／隐藏侧栏，显示时聚焦列表，左右切换分类、上下选择、Enter 插入；Alt+E 显示并聚焦常用短语，Enter 直接发送。Alt 导航键占用冲突会提示。

序号话术快捷键默认关闭，十项默认绑定 Ctrl+1—9、Ctrl+0。点击按键框录入单组合键，“关闭”清空单项，重新录入即可恢复。开启后关闭设置窗口生效，默认插入，勾选“直接发送”后发送。序号对应主窗口当前绘制的编号，折叠后连续编号；主窗口搜索替代普通列表，文件槽位不触发话术，搜索加载和组合输入期间暂停。隐藏主窗口后沿用最后列表，底部搜索不改变序号映射。

自定义话术快捷键通过“功能键／第一键／第二键”录入，兼容原单组合键。`Ctrl+Y+C` 表示按住 Ctrl 依次按 Y、C，`1+1` 表示两次独立按 1，第二键需在一秒内按下。完全同键可绑定多条话术，单条也显示候选；候选覆盖全部本地活动话术，按分类和话术顺序排列。上下键选择，数字 1—9、0 插入前十项，空格插入当前项，Enter 直接发送，Esc 取消；超过十项继续用方向键选择，候选选择不限时。白底蓝细框候选不激活、不占任务栏，优先在目标输入位置上方显示并限制在工作区内。

序号与自定义话术各有独立开启开关，共用“全局生效”：默认只在闪语或记录的目标窗口生效，开启后可用于其他前台窗口。编辑、录入、模态交互和设置窗口存在期间暂停业务快捷键；搜索允许已配置的序号组合键。触发键完整匹配后消费，未完成序列在原输入区回放；候选期间切换窗口、输入控件或点击外部区域即取消。单键与双键前缀冲突，以及序号之间、序号与导航或自定义话术的冲突会显示中文原因并保留原配置。

发送统一使用 Windows 剪贴板和按键。插入和发送会替换原剪贴板，结束后保留最后写入的内容块，不备份或恢复旧内容；期间发生新的复制会立即停止并保留新内容。目标输入区需要支持对应的文字、图片或文件格式；发送键应与目标软件一致。程序记录的是系统操作提交情况。企业微信识别仅用于窗口吸附。

## Hub 部署

服务端项目：[QuickPhrase-Hub](https://github.com/thelinyue/QuickPhrase-Hub)（源码私有）。镜像公开，部署者无需访问源码或登录 GHCR。公开镜像支持 Linux x64（`linux/amd64`），客户端支持 Windows x64。

在 Docker／NAS 的图形界面中新建 Compose 项目，选择一个固定的项目目录，粘贴下面的完整配置。将 `SHANYU_ADMIN_PASSWORD` 的空字符串填写为自己的初始密码，再点击部署。密码至少8个字符，建议12位以上随机字母和数字；没有公开默认密码。

```yaml
services:
  quickphrase-hub:
    image: ghcr.io/thelinyue/quickphrase-hub:0.2.0
    user: "0:0"
    restart: unless-stopped
    ports:
      - "7823:7823"
    environment:
      SHANYU_ADMIN_USERNAME: "admin"
      SHANYU_ADMIN_PASSWORD: ""
    volumes:
      - "./data:/data"
```

服务名称统一为 `quickphrase-hub`。旧项目使用 `shanyu` 时，在图形界面先停止并移除旧容器，保留原项目目录和 `data`，再应用新配置，避免同时启动两个服务。0.2.0镜像继续使用上面的 `SHANYU_*` 初始化变量；当前0.2.1源码新增 `QUICKPHRASE_*` 名称并兼容旧变量，新名称需配合后续镜像使用。

默认用户名为 `admin`，可自行修改；首次登录必须修改初始密码。用户名支持1—64个字符的普通名称，昵称和联系方式可选。已有数据库不会被初始化变量覆盖；初始化完成后可从图形界面移除初始密码变量。

`./data:/data` 把项目目录下的 `data` 保存到宿主，首次部署可自动创建。单容器直接以 root 运行，无需额外初始化容器或终端权限命令。客户端在“账号与同步”填写 `http://服务器IP:7823` 并登录。HTTP 适用于可信局域网，公网使用 HTTPS 反向代理；客户端不降级或跳过证书校验。代理需关闭 SSE 缓冲和缓存，并允许128MB上传。

升级时先在图形界面停止容器并完整备份原 `data`，再替换镜像版本；核对实际项目目录及挂载，保留旧目录和卷。已有 UID10001 数据可由 root 接入，服务不递归改写原素材属主。root 新建文件可能归 root；回退到非 root 镜像前须停服核对读写权限。不要删除数据卷或覆盖运行中的数据库。

共享数据备份包含账号、共享库、云文件、回收记录及实际素材，排除个人内容和会话；个人内容使用个人完整备份。完整运维备份在停服后保存整个 `data`。全目录恢复须使用同一份备份还原到新目录，并执行恢复准备以清除旧会话、更换个人同步世代；维护流程见下文。

可复制的配置及备份细节见[共享库与部署](docs/team-sharing.md)，本版变化见[0.2.0 发布说明](docs/releases/v0.2.0.md)。

## 数据与备份

数据默认位于 `%LOCALAPPDATA%\com.quickphrase.desktop`：`shanyu.sqlite3` 保存分类、话术、有序内容和设置，`images` 保存图片，`thumbnails`／`temp` 是可清理缓存，`shanyu.log` 记录中文错误。

0.1.1 的数据库统一使用版本1的完整初始结构。已有开发库打开时按实际字段和索引无损整理并统一版本标记；后续正式版本按数据兼容需求增加数据库版本。

缓存管理按“一键删除”和“清理本地缓存”分区，仅展示本地可用功能。全部我的话术删除前确认数量，默认进入回收站；取消回收选项才会永久删除。常用短语删除前明确提示不可恢复，建议先导出完整备份。整库删除保留分类、图片素材、文件关联及旧回收记录；其他窗口新增或删除内容后，旧确认会被拒绝，需要重新确认。清理缩略图或临时文件只移除可重建缓存。

导入导出统一在设置中选择个人库或共享库；共享库菜单会预选当前组。个人全部分类导出为“完整备份”，分类及共享库导出为“话术包”。ZIP版本2保存图片和话术附件的实际内容；个人全库另含常用短语、回收和设置。账号导出当前本机版本，包含待同步修改及库内待确认便携设置，不强制同步。共享库仅包含在用内容，不含回收、成员和角色。独立文件库仍只保存路径关联，源文件需单独备份。ZIP未加密。详见[导入导出](docs/data-transfer.md)。

导入先预览，确认后生成独立副本；同一批次的ID和素材固定，重试不重新复制。合并同名分类及恢复设置默认关闭；合并只匹配同级唯一同名项，多项同名时独立导入并提示。含独立文件关联的本机备份只能导入本机个人库。共享库导入要求联网、首次改密完成及编辑权限，仅导入在用内容。私人失败整批回滚并清理本批素材；共享库结果不明先核对，不盲目重发。发送和快捷键恢复需本机确认，占用不阻塞正文。分类复制／移动的原有同名处理保持原规则。Excel仅保存文字，不能保存图片、附件和完整分段结构。

安装、升级和卸载保留用户数据。产品的安装 AppId 和内部数据标识保持一致，以支持后续升级。

个人完整备份包含回收记录及其实际素材，导入后保持删除状态，需要显式还原。旧完整ZIP及服务器个人ZIP仍可导入。离线素材齐全时可导出；缺素材或取消不会替换已有备份。永久删除或清空回收站只移除记录，不自动删除素材图片或外部源文件。

## 开发与构建

需要 Windows x64、Rust MSVC 工具链、Visual Studio C++ Build Tools／Windows SDK、Node.js 22.22.2／24.15.0以上的相应偶数主版本或26+ 和 WebView2。当前验证环境为 Windows 11 26200、Rust 1.99.0 stable、Node 24.18.0、WebView2 154.0.4258.62。2026-10-11 已将15个 npm、16个 Rust直接依赖升级到各自最新稳定版，并更新锁文件；间接依赖使用上游允许的最新兼容版本。当前使用 React19.3、TypeScript7.0.2、Vite8.3.4、Vitest5.0.3、Tauri2.12.3；开发环境要求以 `package.json` 的 Node engines 为准。

```powershell
npm ci
npm run tauri -- dev
```

使用 Inno Setup 6 生成安装包：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/build-release.ps1 -InnoCompiler "C:\Program Files (x86)\Inno Setup 6\ISCC.exe"
```

脚本运行 Tauri `build --no-bundle`，下载并校验微软 WebView2 引导程序的签名，然后调用 ISCC。可通过 `INNOSETUP_ISCC` 或 `-InnoCompiler` 指定编译器路径；`-SkipInstall` 复用已安装的 npm 依赖。当前源码为尚未发布的0.2.1，产物为 `artifacts/QuickPhrase-Setup-0.2.1-x64.exe`，主程序为 `QuickPhrase.exe`；新安装默认使用当前用户的 `Programs\QuickPhrase`，升级沿用原安装目录，无需管理员权限。已发布0.2.0的下载文件仍使用原 `Shanyu` 名称。

默认仍只生成安装器。候选构建可加 `-Version 0.2.1-rc.1`，版本通过临时 Tauri 配置传入，不修改源码或锁文件；设置页显示实际应用版本。需要发布资产时另行运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/package-release.ps1 -Version 0.2.1`，从当前对应版本的程序和安装器生成 `artifacts/release/0.2.1` 下的 ZIP、安装器、原有 SHA256 清单及 manifest。ZIP 需要本机已安装 WebView2。

GitHub 自动 CI 执行单测、静态检查与 Debug 构建。候选和正式发布均只允许手动触发并复用 CI：候选从 `master` 构建 `0.2.1-rc.N`，保留企业微信人工验收确认，仅上传 Actions artifact；正式发布在 `master` 手动触发，各阶段均检出对应版本标签，源码版本、标签与提交必须一致，并确认企业微信及 Windows 11 安装矩阵。当前实机缺口见验收记录，不能勾选确认来代替实际验证。工作流不会覆盖既有标签或 Release。

执行真实 Windows 验收：

```powershell
npm run build
cargo build --manifest-path src-tauri/Cargo.toml --features custom-protocol
node scripts/verify-background-following.mjs
node scripts/verify-hover-docking.mjs
node scripts/verify-mouse-latency.mjs
# 可选双屏专项：目标固定96 DPI，实际覆盖100%和150%显示器；单屏会明确跳过
node scripts/verify-hover-docking.mjs --dpi
node scripts/verify-categories.mjs
node scripts/verify-library.mjs
$env:SHANYU_TEAM_SERVER_EXE = 'D:\code\QuickPhrase-hub\target\debug\quickphrase-hub.exe'
node scripts/verify-transfer.mjs
node scripts/verify-company.mjs
npm run test:native
npm run test:native -- --dock-only
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/shortcut-desktop.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/verify-installer.ps1 -InnoCompiler "C:\Program Files (x86)\Inno Setup 6\ISCC.exe"
```

调研企业微信的 UI Automation 可访问性时，在聊天、搜索及图片页面分别运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/inspect-wecom-input.ps1`。此调研脚本不参与吸附识别，只读控件类型、标识、状态和边界，不读取正文、不点击或发送；默认检查主窗口，可用 `-Handle` 指定窗口。没有运行企业微信时明确报错，不启动企业微信。

原生验收使用独立数据目录、Debug 单实例标识和本机输入宿主，可以保留正式客户端运行。`--dock-only` 只运行主窗口吸附和底部短语横条两组检查。吸附测试使用专用 ShanyuDockHost.exe，仅隔离 Debug 客户端识别。后台跟随专项覆盖普通／开机／重复启动、独立唤起、隐藏恢复、任务栏样式和多窗口遮挡，悬停专项覆盖预览与稳定宽度；这两项不使用系统剪贴板或聊天发送。原生脚本需顺序运行，执行时暂停键鼠操作；发送验收会短暂使用剪贴板，结束时仅恢复仍属于本次验收的内容，保留后来的用户复制。安装验收仅运行安装器，使用独立 AppId、编译时菜单组、启动项和安装目录，验证已发布0.2.0旧安装器夹具的改名升级；需保留其 shanyu.exe 构建产物，完成后清理自己的测试安装。报告和截图位于 `.build` 下对应的专项目录。

鼠标延迟专项运行前退出普通客户端，避免旧实例的全局钩子干扰测量。每组120次左右1像素往返移动，不点击、不按键、不访问剪贴板；比较未启动、关闭吸附、正在吸附、连续移动缩放及退出后的钩子链延迟。检测到其他鼠标移动时不恢复旧光标位置，避免覆盖用户后来移动的位置。

快捷键专项 `tests/shortcut-desktop.ps1` 在独立 Windows 输入桌面运行完整监听与发送链路，结束后切回原桌面，使用标准 WinForms 输入宿主。隔离 Debug 实例才接受带专用标记的测试按键。报告和宿主草稿／发送记录保存在 `docs/ui/runtime/shortcuts`，历史渲染截图已清理；这些渲染倍率不代表系统 DPI 或真实聊天软件验收。可加 `-Filter Alt` 单独复现导航组。

`verify-categories.mjs` 和 `verify-library.mjs` 使用隐藏的隔离客户端，两者需顺序执行。最新两组共63项通过，覆盖空分类创建与删除、设置同步、备份、顺序双键录入、点击规则、底部搜索、图片粘贴、回收站、文件菜单和本地缓存管理。缓存专项实际执行批量删除、还原及缓存清理，并验证确认期间新增内容会被拒绝、素材和源文件逐项保留。实际DOM、Rust业务服务和SQLite均执行；发送路由只记录参数并模拟返回，原生菜单弹出、系统对话框、文件打开、系统剪贴板和系统聚焦被抑制。它们不能替代实体快捷键触发、真实发送、吸附或安装升级验收。
