# 账号与同步（0.2.0）

客户端与 Hub 分仓维护，一个部署对应一台 Hub。服务端端口7823，数据映射 `./data:/data`，支持可信局域网 HTTP 和校验证书的 HTTPS。首次管理员沿用环境变量初始化、首次改密及 Windows 凭据管理器。

## 使用

“设置→账号与同步”连接用户名，首次默认不同步个人库。选择“开启同步”预览分类、话术、常用短语和设置，同 ID 选择“使用服务器”“使用本机”或“保留两份”；设置只有前两项。日常只使用“个人话术”；原本机内容保留，可在“导入数据→找回旧本机内容”预览后导入，不再切换原本机库。不同 ID 全部保留，不按名称合并分类，只有保留两份分配副本 ID；失败重试复用合并映射。

开启后按服务器和不可变 `userId` 保存独立账号库。退出仍可查看、投递、增删改个人内容，同账号登录继续同步；其他账号不能自动带入旧账号内容。暂停保留当前内容和待同步改动，重启及重新登录不会取消暂停。更换账号或服务器后使用各自独立的个人内容，新账号从空库开始，不自动带入历史本机内容；尚未绑定过账号的新用户首次登录保留当前本机内容，首次开启同步才确认合并；即使尚未开启同步，换到新账号也不会带入这些内容，换回原账号可继续使用。

共享话术通过“共享话术：库名 ▾”切换；断网和离线重启可使用已缓存内容，禁止离线编辑管理。退出清理共享话术缓存，联网先刷新授权，移库、停用和删除清理相应缓存。离线撤权需再次联网才生效，个人副本和已发送内容不能收回。

退出后账号页仍显示所属账号、最近同步时间及“未登录，内容保留在本机”。个人库最近同步时间为本设备成功完成服务器核对且没有待提交、结果待确认、冲突或恢复待核对内容的完成时间；无变化的成功核对也更新。失败、暂停和旧会话响应不更新，重启保留；旧库无记录显示“暂无成功同步记录”。使用客户端系统时间，按系统时区显示，不代表所有附件已缓存或发送设置已在本机应用。共享话术按每个库分别记录授权和内容核对成功时间，离线重启保留，退出或撤权随缓存清理。

状态使用“已同步”“同步中”“待同步”“离线”“有冲突”。话术缺少素材时显示“未缓存”，右键“下载素材”，下载完成后重新触发投递。不会因素材后来就绪而自动发送。

## 设置和本机数据

同步白名单覆盖显示、主题、搜索、发送偏好、点击行为、个人快捷键和编号绑定。窗口位置尺寸、个人话术／共享话术入口顺序、吸附、置顶、开机、托盘和连接凭据保留本机，独立文件库不上传。新增入口顺序不扩展当前服务端设置白名单，避免旧服务端拒绝同步请求；切换账号和云端配置更新保持本机入口顺序。

首次有云端设置默认采用服务器，在预览中确认。后续外观、搜索自动应用；发送、点击、快捷键需要“设置待确认→应用本机”。云端配置与本机生效配置独立保存，系统占用或未应用的绑定不会反写清空云端，也不阻塞正文同步。若字段组合冲突，保留本机配置供核对。

统一使用“设置→导入数据／导出数据”，不再提供独立个人备份按钮。账号完整备份来自当前本机库，包含待同步修改及待确认便携配置，不含独立文件及设备设置。含独立文件关联的旧完整备份分为“个人内容”和“本机文件与设备设置”两次预览与提交，不再要求切库。详细范围及重试规则见[导入导出](data-transfer.md)。

## 同步边界

公共协议在 `crates/team-model`，个人库使用独立类型及 `/api/me/private`，不作为特殊共享话术。`/api/me` 返回能力；旧服务端不支持时只提示升级，共享话术继续兼容。个人素材、快照、请求结果、变更和个人备份的归属只从会话取得，管理员也不能指定其他用户 ID。

本地内容与待同步键在 SQLite 同事务提交；每个活动个人库只有一个同步循环，SSE 唤醒和60秒检查合并处理。记录版本、设置字段版本及永久删除标记阻止长期离线设备恢复已删除内容。无关内容继续同步，结构冲突保留分类上下文及草稿。

写前持久化请求 ID、内容及本地修订。超时先查询结果，仅同 ID、同内容重试；确定拒绝后保留草稿、重建请求。确认只清理对应修订的队列，新编辑仍待同步。会话、库身份、同步世代和版本共同约束旧响应落盘。

附件先复制到受控目录，128MB单素材上限，流式上传下载；最多两个下载任务，当前分类图片优先缓存，附件按需下载。沿用图片16384像素及128MB解码分配限制，不删除外部源文件。

编辑与投递携带库身份、内容 ID 和本地修订；旧编辑窗口及旧显示版本拒绝覆盖。投递开始后固定内容和素材，复用已有发送锁、目标校验、剪贴板保护和中断规则，不自动重发。

## 备份恢复和隐私

- 共享数据备份：账号、共享话术、云文件、回收记录及实际素材，排除个人内容及会话凭据。
- 个人完整备份：在统一导出入口选择个人全部分类，保存本机内容、回收、常用短语、设置和实际素材。账号库只保存便携配置，含待确认值；缺素材不能生成成品。旧服务器个人ZIP继续兼容导入，现有服务端接口保留。
- 完整运维备份：停服保存整个 `./data`。恢复同一份双库及素材，启动前运行 `--prepare-restore`，清除会话、更换个人同步世代。客户端保留旧改动，重新预览核对后继续同步，禁止直接回放旧队列。账号按 `userId` 匹配。

服务管理界面没有用户个人库的查看或导出入口。本版没有端到端加密；服务器维护者和能够重置密码的管理员仍可能接触个人数据。

## 验证

运行 README 中前端、Rust、发布脚本检查；Windows 实际 IPC 联调：

```powershell
$env:SHANYU_TEAM_SERVER_EXE = 'D:\code\QuickPhrase-hub\target\debug\shanyu-team-server.exe'
node scripts/verify-teams.mjs
node scripts/verify-private.mjs
node scripts/verify-transfer.mjs
```

服务端混合压测使用 `cargo test --locked --release --test groups fifty_online -- --nocapture`。容器实际迁移、重启、备份和恢复由 Linux CI 执行。回环网络、隔离宿主及模拟确认不能替代真实企业微信、局域网5秒目标、反向代理、安装升级与DPI验收；正式客户端及镜像由负责人手动发布。
