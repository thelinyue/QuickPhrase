# 闪语统一样式规范

本规范覆盖全部 Tauri 客户端窗口，包括闪云中心；不覆盖独立 Hub 服务端。不换主题、布局或 UI 框架，一致性来自共用变量、基础控件和实际界面回归，而非另建一套页面级外观。

运行时数值以 `src/styles/tokens.css` 为准。本文解释变量用途、复用方式和有意保留的差异，修改时同步维护。历史截图、测试数量和旧发布状态已移至 [历史验收记录](ui/theme-history.md)，不能作为当前验收证明。

## 视觉材料

| 用途 | 变量／规格 | 规则 |
|---|---|---|
| 正文、辅助文字 | `--theme-text`、`--theme-muted` | 正文白底；辅助文字仍需可读，不把降低透明度当作说明文字配色 |
| 主操作、悬停主色、反白文字 | `--theme-accent`、`--theme-accent-hover`、`--theme-on-accent` | 默认主色 `#4B6479`；七种主题只改配色，共用控件与布局 |
| 表面、辅助区域、分隔线 | `--theme-surface`、`--theme-panel`、`--theme-line` | 辅助区域由主色轻染；普通面板、列表不增加装饰阴影 |
| 控件边框 | `--theme-control-line` | 仅表单与有边框按钮；聚焦只换颜色，不加粗边框 |
| 悬停、选中 | `--theme-hover`、`--theme-selection` | 两者分开；列表悬停覆盖选中底色，移出恢复 |
| 成功、警告、危险 | `--theme-success`、`--theme-gold-text`、`--theme-danger` | 分别搭配 `--theme-success-soft`、`--theme-gold-soft`、`--theme-danger-soft`；危险悬停使用 `--theme-danger-hover` |
| 话术标题、分类 | `--phrase-title-color`、`--category-*` | 七种主题共用暖橙标题、浅杏普通分类与深橙当前分类，不借用危险色 |
| 字体 | `--font-ui`、`--font-code` | 沿用 Windows 字体栈；代码正文使用 Consolas／Cascadia Mono |
| 字号 | `--font-caption/small/body/group/dialog/page/detail` | 11／12／13／14／16／18／20px；话术使用用户的 `--phrase-size`，保持 10—18px |
| 控件尺寸 | `--control-height`、`--control-height-compact` | 常规 32px，紧凑 28px；宽度随内容与布局，不压缩文字来塞进窄窗 |
| 通用间距 | `--space-1` 至 `--space-6` | 4／8／12／16／20／24px；不机械替换几何补偿、光学对齐及实际测量值 |
| 圆角 | `--theme-radius`、`--radius-popover` | 普通控件 6px，分类标签和常规浮层 8px；主窗口外框及独立短语菜单保留直角 |
| 阴影 | `--shadow-popover`、`--shadow-modal` | 只用于浮层和模态；不为普通按钮、列表增加装饰性阴影 |
| 图标 | `Icon`、`FileIcon` | 普通操作 18px，分组操作 16px、类型识别等按用途使用 20px；系统文件图标保留原识别色，不混入其他图标库或 Emoji |

保留 `--blue`、`--blue-light`、`--orange` 和 `--line` 的旧变量兼容入口；新业务样式引用语义变量，不各自定义另一套品牌色。默认正文、辅助文字、主操作和状态文字在规定表面上的对比度至少 4.5:1；禁用态不是普通正文。

## 共用控件

### 按钮

从 `src/ui.tsx` 导入 `Button`／`IconButton`。不要复制一套 `xxx-primary`、`xxx-button` 颜色、圆角和状态规则。

```tsx
<Button onClick={cancel}>取消</Button>
<Button variant="primary" type="submit" busy={saving}>保存</Button>
<Button variant="ghost" size="compact" onClick={refresh}>刷新</Button>
<Button variant="text" onClick={showDetails}>查看详情</Button>
<IconButton size="compact" aria-label="刷新" onClick={refresh}>
  <Icon name="refresh" />
</IconButton>
<Button variant="primary" danger onClick={remove}>永久删除</Button>
```

- `variant` 为 `primary`／`secondary`／`ghost`／`text`，默认 `secondary`；`size` 为 `regular`／`compact`，默认 `regular`。
- `danger` 与外观规格正交；危险实心按钮在悬停后仍为红色、白字，危险文字操作仍为红色。
- 默认 `type="button"`。所有表单提交明确写 `type="submit"`，包括登录、文件关联和回收确认，不能依赖 HTML 的隐式提交默认值。
- `busy` 禁用按钮并设置 `aria-busy`；提交文案由业务明确提供。组件不接管异步请求、重试、发送防重或权限判断。
- `ref`、事件、表单属性、`aria-*`、`data-*` 等原生属性透传。图标按钮必须有 `aria-label`，提示文字不能代替可访问名称。
- 页面内动作不要靠 `className="danger-dialog"` 改颜色。`FormDialog` 使用 `spec.danger` 表达危险确认。

### 表单与弹窗

`input`、`select`、`textarea` 直接使用原生标签，统一材料来自 `controls.css`，不另加同义包装组件。业务 CSS 只设置宽度、排列、换行和滚动；密码显示切换等组合控件可保留专用定位。

- 单行控件 32px，多行控件最小 64px，可按正文需要增长；窄窗口让标签或成对字段换行。
- 使用原生 `required`、类型及范围校验。失败保留输入，给出清晰中文原因，不把无效数据当作空数据。
- 使用现有 `Titlebar`、`FormDialog`、`Feedback` 和账号弹窗结构。提交时保留原来的同步锁、字段禁用、Escape 保护与关闭后的焦点恢复。
- `details/summary` 操作入口使用共用 `ui-disclosure` 材料；业务只控制弹层位置和菜单宽度。

### 关闭方式

- 页面内弹窗的标题右侧固定显示“关闭弹窗”×；它与底部“取消／关闭”、Esc 调用同一个 `useModalClose` 请求，只关闭当前弹窗，不退出宿主窗口。
- 点击遮罩或窗口失焦不关闭表单与确认框。菜单、色板等轻量浮层仍可外部点击收起；Esc 先由最上层浮层消费，不连带清空父页面搜索或退出父编辑器。设置、管理主页面不增加 Esc 退出整窗。
- 未修改或已改回原值直接关闭；有编辑草稿／权限调整时询问一次“放弃未保存的修改？”。拒绝后保留内容、错误及焦点；确认进行中不能重复弹出询问。成功关闭弹窗后恢复打开入口的焦点。
- 保存、删除、导入等提交期间禁止关闭，鼠标入口与原生关窗不能绕过同步提交锁。失败保留原表单供检查与重试；成功完成提交不再次询问是否放弃。
- `FormDialog` 使用 `DialogHeader` 与初始字段值比较草稿。仅用于安全复核的删除名称／回收选项显式声明 `spec.hasDraft: false`，避免“取消确认还要再确认”；这不跳过提交锁、权限、名称校验或事务。
- 每个独立窗口的 `WindowCloseScope` 只安装一个原生 `onCloseRequested`；子表单通过 `useCloseGuard` 提供当前草稿／提交状态，不另装互相无法否决的销毁监听。新增可编辑独立路由时，同步接入 `App` 的关闭保护范围及对应窗口的最小销毁权限。
- 独立窗口标题栏的“关闭窗口”×、Alt+F4 和编辑／排序窗的取消、Esc 均经过窗口关闭保护。原生模态使宿主标题栏 inert 时，使用 `DialogWindowClose` 在宿主原位置代理 ×；它不是弹窗自身的关闭按钮。
- 设置沿用自动保存：原生关闭先提交仍聚焦的自动保存字段，再等待现有 `flush`；保存失败留窗。关闭管理窗口不停止 Rust 后台上传／下载队列。主窗托盘隐藏语义、搜索清空确认的 Rust 级关窗互斥、只读指引窗的 Esc 保持原实现。

关闭保护只在当前窗口内汇总状态，不创建全局弹窗管理器、额外设置、数据库字段或 IPC。实现与本轮验证见 [2026-11-02 关闭方式统一](ui/dialog-close-2026-11-02.md)。

### 交互状态

| 状态 | 统一反馈 | 不能发生 |
|---|---|---|
| 正常 | 对应语义表面、文字及 1px 边框 | 页面自行重新配色 |
| 悬停 | 浅底／实色加深；文字操作加下划线 | 危险操作变成品牌色、禁用按钮出现可操作反馈 |
| 按下 | 明暗加深 | 改 padding／边框宽度导致跳动 |
| 键盘焦点 | 按钮与列表行明暗、表单浅底与边框换色；链接下划线 | 追加 outline 或外扩焦点环、简单删除所有反馈 |
| 选中并聚焦 | 保留选中底色和标记，再叠加明暗 | 用同一个选中色覆盖聚焦，导致无法分辨键盘位置 |
| 色块聚焦 | 降低透明度，兼顾纯黑与纯白 | 仅降低亮度，使纯黑色块看不出焦点 |
| 禁用／处理中 | 原位置保留，降低明度与透明度；拒绝操作 | 移除控件占位、自动重试已经执行的业务动作 |

话术、文件、搜索和候选的选中标记只绘制左侧线；发送入口始终预留 24px 列，显隐不移动标题。列表悬停覆盖选中底色，鼠标移出恢复。普通滚动正文的键盘位置使用浅底；只读成员名单继续白底。

### 提示与空态

复用 `Feedback`／`AccountNotice` 和现有鹦鹉插画。成功短暂显示，失败保留至明确关闭；悬停、聚焦或展开详情时不自动关闭。长信息默认紧凑截断、按需展开，不能挤占主操作。加载、读取失败、真正空数据和搜索无结果分别表达；不能在读取失败时展示“空库”。

## 样式分层

`src/styles.css` 是唯一入口，加载顺序固定为：

1. `styles/tokens.css`：主题与设计变量。
2. `styles/base.css`：字体、重置、图标和窗口基础，不承载业务布局。
3. `styles/controls.css`：按钮、原生表单、开关、标题栏、提示、色板、通用弹窗及菜单材料。
4. `styles/main.css`、`settings.css`、`editor.css`、`management.css`、`files.css`、`floating.css`、`cloud.css`：对应业务布局、固定列、滚动及响应式。

不要在入口文件尾部追加同义控件覆盖，不在业务文件重定义普通按钮和输入框材料。改共享规则前核对其最终生效样式与各窗口用途。新增视觉差异必须有明确用途，记录在本节或相关组件旁；不新增 UI 框架、样式 hash、冻结截图 baseline 或发布 gate。

动态行内样式允许用于用户自定义色、菜单坐标、字号设置及原生测量值。可编辑正文的媒体节点由命令式 DOM 保持光标、撤销与输入法；其删除按钮复用 `ui-button`／`ui-icon-button` 类，附件使用同一 `iconPath`，不另外挂载 React 根。

## 必要例外与安全边界

| 用途 | 保留规格／理由 |
|---|---|
| 主窗与标题栏 | 主窗默认 330×720、最小 300×400 DIP；标题栏 40px，主搜索 36px；不为统一控件改变原生窗口几何 |
| 设置侧栏底部 | 只显示“闪语”和可用版本号；工具定位说明保留在关于页，不在侧栏重复 |
| 主窗列表 | 话术行 32px、分组 28px、发送列 24px、正文起点 26px；字号 10／14／18px 均不推动列位 |
| 原生专用入口 | 标题栏图标热区 26×28、分类标签 24px、历史 22px、短语 24／25px、媒体删除 18px、紧凑提示 24px；它们不是新的普通按钮规格 |
| 候选／预览 | 候选保留单行与字体相关测高；预览只展示真实标题，空标题和纯空白标题不使用正文或媒体名称兜底。无标题且无快捷键时省略顶部区域，仅有快捷键时靠右保留；预览按实际内容和鼠标下方工作区自适应。表头、底栏、无激活显示、DPI 换算及裁切继续由现有前后端配合 |
| 云文件与命令 | 模块切换使用 28px 紧凑规格，保留默认窗十条记录与分页、最小 760×480 DIP 滚动；命令保留列表／正文阅读布局与窄窗返回，不强行统一为表格 |
| 账号内容列 | 行内昵称、联系方式和共享库名允许收缩、省略，保留正文色；操作按钮与图标不收缩，避免长内容挤出最小客户区 |
| 用户自定义色 | 单条话术优先于全局颜色，再由主题提供默认色；空值和历史 `#ff5100` 只在显示时解析，不改写用户记录、不强行修正自定义色对比度 |
| 系统界面 | Windows 原生菜单、文件对话框与系统文件图标由系统绘制，不套 WebView 材料 |

本轮不新增设置项、数据库字段、IPC 或 Hub 协议；发送、权限、目标复核、事务及剪贴板保护保持原实现。系统提交成功不等于目标应用最终发送成功。

## 验证方法

- 组件与行为：`npm test`，包含 `src/ui.test.tsx` 的原生属性／ref、鼠标与键盘、显式提交／无效输入、禁用／处理中、防重复、失败草稿及焦点恢复。
- 静态与构建：`npm run check`、`npm run build`、项目现有 Rust 格式、测试、Clippy 及 `custom-protocol` 构建。
- 实际 WebView2：构建后运行 `node scripts/verify-illustrations.mjs`；七种主题检查共用控件主要状态、计算样式、尺寸不变、对比度及截图，并覆盖独立窗口、最小视口、长中文、字号及空态／失败态。
- 管理与闪云：沿用 `verify-teams.mjs`、`verify-company.mjs`、`verify-cloud-commands.mjs` 等隔离专项；需要服务端时显式提供 `SHANYU_TEAM_SERVER_EXE`，不连接真实生产数据。
- 100%／150%／200% 系统 DPI、跨屏、原生无激活窗口、企业微信及安装升级需要单独实机验收。CDP 视口、强制伪类及像素密度模拟不能代替它们。

本轮结果与未验证事项见 [2026-11-02 样式统一验收](ui/style-unification-2026-11-02.md)。
