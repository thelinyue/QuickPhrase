# 问题诊断

在“设置 → 问题诊断”选择问题，点击“开始记录”。设置会按原有保存保护关闭，请回到原窗口复现；之后回到此页点击“停止并导出”，将 ZIP 和复现时间、步骤交给开发者。最多记录 5 分钟，也可以导出上次运行留下的记录。取消保存或导出失败不会清除证据。

| 问题 | 当前记录范围 | 不能据此确认的事情 |
| --- | --- | --- |
| 快捷键与输入法 | 本人/成员绑定数量、目标与焦点保护、匹配结果、相关键的角色和按下/松开、钩子放行结果、候选与投递步骤 | 不读取实际字母；IME 组字状态记为未知；放行不等于目标收到 |
| 账号与同步 | 登录、授权、本人/成员/共享请求、素材下载及本人素材上传的状态和耗时 | 不记录 URL、账号、令牌、参数或正文；请求成功不等于同步已落库 |
| 窗口与显示 | 自有窗口位置、尺寸、DPI、候选实际定位 | 不能替代真实多屏验收 |
| 卡顿与响应 | 读取库/搜索/成员视图/共享视图/保存设置/保存话术的耗时，WebView 与原生循环响应间隔 | 不是采样分析器；后台 WebView 调度间隔不能直接当作 CPU 卡顿 |
| 异常退出线索 | 自动附带最近一次 Rust panic 时间 | 不覆盖所有系统异常、强杀或断电；不包含内存转储 |

这是定位证据的入口，不保证覆盖所有软件或输入法问题。更新下载、AI 连接、全部网络流式传输、系统级崩溃与深层性能问题尚无完整专用追踪；没有日志不等于没有故障。

## 隐私与保存

- 事件只接收固定枚举与数值，不接收任意日志字符串。不导出实际按键码、快捷键字母、正文、密码、令牌、窗口标题和用户路径。
- 不自动截图、上传或收集内存。原有 `shanyu.log`、数据库和素材目录不打包。
- 日常摘要最多 256 条、临时详细记录最多 4096 条、队列最多 512 条。满载覆盖旧记录或丢弃新事件，保留计数，不阻塞键盘钩子。
- 快照保存在固定应用本地目录的 `diagnostics/records.json`，每两秒写入，异常退出可能丢失末尾。移动业务数据不搬走诊断记录。重启恢复证据，不自动恢复详细采集。
- 在“记录说明”中清除本地记录。导出先写临时文件再替换 ZIP，失败保留原快照和内存证据。

## 开发者读包

ZIP 仅含 `说明.txt`、`manifest.json`、`events.jsonl`。manifest 提供应用版本、Windows build、架构、记录范围、覆盖/丢弃计数、异常退出时间，以及 `imeComposition: unknown`、`targetReception: unverified`。

事件按 UTC Unix 毫秒排序，`process` 是本次进程启动的毫秒时间，不是机器或用户标识。每条记录的 `event` 对象使用静态类型名。网络 `request` 是进程内递增编号，与 `process` 一起配对并发请求，不含账号或素材 ID。

- `bindings`：不同快捷键数量、含绑定的成员话术数量、代次、本机开关；没有绑定字符串或话术标识。
- `key.role`：1 绑定首键、2 后续键、3 候选操作键。多角色时首键优先。`local_blocked` 表示闪语拦截，`chain_blocked` 表示钩子链返回，均不能确认输入法收到事件。
- `context`：目标是否匹配、管理窗口与投递保护、上下文可用及变化；不记外部句柄、标题、进程名或控件文字。
- `candidate.action`：1 打开、2 取消、3 重新测量。
- `layout.window`：1 主窗口、2 话术候选、3 搜索、4 设置、0 其他自有窗口；坐标与尺寸为物理像素。
- `delivery.stage`：0 开始、1 准备、2 目标复核、3 粘贴提交、4 等待、5 发送键提交、6 清理。结果仅表示系统操作是否成功，不代表聊天应用最终已发送。
- `network.stage`：0 开始、1 响应头、2 当前步骤完成、3 失败/取消等未完成。普通请求观测至响应头和 HTTP 状态检查，不能确认响应体解码、授权落盘或后续同步成功。`failure`：0 未分类（含 HTTP 错误/取消）、1 超时、2 连接失败、3 解码失败、4 其他传输错误。
- `ipc`：白名单操作结果及耗时；`operation: heartbeat` 为 WebView 调度间隔。单独的 `heartbeat` 事件来自原生循环。

记录缺口、未复现或环境不支持时保留“未确认”，不得自动归因于候选遮挡、输入法吞键或服务器故障。
