# 2026-11-02 关闭方式统一

## 本轮范围

用户采纳推荐方案后实施。此前统一样式和移除设置侧栏“本地话术工具”的工作保留；这里只记录本次关闭行为，不把此前验收结果当作本轮证明。不提交、推送、打标签、制作安装包或正式发布。

## 实施

- `FormDialog`、账号同步／成员弹窗、快捷键、云命令、闪云权限及回收确认统一自身 ×、取消／关闭和 Esc。遮罩／失焦不关闭表单；轻量菜单继续外部点击收起。
- 关闭有实际编辑草稿的表单需要一次明确确认；拒绝保留输入、错误和焦点。安全复核的名称／回收选项不是内容草稿，取消不追加确认，原校验与危险操作保护不变。
- 成员角色按当前人员和角色与已保存值比较；调整后改回原值不再被视为草稿，保留原有函数式更新，避免异步添加成员丢失其他调整。
- 独立话术编辑器、文件关联、常用短语、快速排序、云文件选择和删除确认登记草稿或提交锁。提交成功后再标记当前内容已保存并关窗；失败不放弃输入。附件导入期间也不能原生关闭。
- `WindowCloseScope` 在一个窗口内汇总状态，只有一个原生关闭监听。实际查证 Tauri 的每个 `onCloseRequested` 都会自行决定 `destroy`，旧闪云中心同时挂命令／权限监听时，一个监听的拒绝不能阻止另一个监听销毁窗口；已去掉这组重复监听。
- 独立窗口的宿主 × 与弹窗自身 × 使用不同可访问名称和位置。模态使宿主自绘标题栏 inert 时，在原宿主 × 位置保留代理按钮，所有代理仍经过统一窗口保护。
- 设置保留自动保存等待／失败留窗；补齐 Alt+F4 未产生 DOM blur 时仍提交当前自动保存输入。未给设置／管理主页面新增 Esc 退出。
- 不把后台上传／下载队列当作窗口提交锁；关闭管理窗不取消它们。主窗的 Rust 托盘隐藏、搜索清空确认的 Rust 写入／关窗互斥和只读指引窗保持原有边界。

没有引入全局弹窗管理器、新依赖、设置项、数据库或 IPC。未改 Rust、Hub 源码及发送、剪贴板、账号世代、权限冲突、内容主键和事务边界。新增 `editor-close.json`，只为这批接入原生关闭保护的编辑／排序／确认窗口授予 Tauri 监听内部所需的 `allow-destroy`；不扩大主窗或只读窗口权限。

## 验证

前端用例先复现了缺少弹窗 ×、取消／Esc 不保护草稿，以及聚焦自动保存输入直接原生关闭丢失修改的问题；再覆盖统一入口、拒绝／接受、防重复、提交锁、失败保留、焦点恢复与 Tauri 每监听各自销毁的语义。
