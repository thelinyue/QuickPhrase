# 云文件：调研与实现

更新日期：2026-10-14。适用版本：当前 0.2.0 开发工作区。范围：Windows x64 桌面及 QuickPhrase-Hub；不包含手机端。功能代码已接入，验收范围与环境缺口见下文。

## 调研依据

[客服宝云文件教程](https://kefubao.com/userHelp/2024-08-29/18.html)标注日期为2024-08-29。本次读取正文及三段桌面操作动图，确认集中上传、设置文件话术标题、其他用户名下载后使用，以及文件名搜索、大小、上传人、上传时间和传输管理入口。没有登录或实测客服宝。

教程显示权限、空间／流量及回收站入口，但未公开其规则；单文件上限、收费、替换、回收保留期和断点续传不属于已证实的竞品能力。闪语采用自身权限和数据安全规则。

## 桌面窗口与使用

- 主菜单“云文件”打开1000×650独立窗口，最小760×480。采用桌面动图中的蓝色标题栏、浅灰左栏、白色内容区和细线表格，支持最小化、最大化／还原及关闭。左上“云文件管理”；左下按权限显示“云文件权限管理”“云文件回收站”。空间／流量收费管理不纳入此次改版。
- 顶部依次为文件名搜索、刷新、下载管理、上传管理、上传新文件。表格显示勾选、文件名、大小、上传时间、上传者和操作；文件名下显示本机下载状态。操作栏仅显示图标，悬停提示名称并保留键盘及无障碍标签；“更多”菜单提供另存为、生成话术。目录、选择弹窗、传输页及回收站统一使用Windows系统关联图标，未下载也能显示。
- 上传时间默认倒序，可切换正序。分页提供前后页、页码跳转及10／20／50条，默认10条；全选仅选择当前页，搜索、翻页、排序或改变每页数量均清空勾选。批量操作在表格上方独立显示，紧邻已选数量，横向滚动时保持固定；文件页及回收站使用相同位置。批量下载在后台执行；批量删除先列出确认清单，再报告各文件结果。
- 上传／下载管理在右侧切换，保留左栏，提供返回、清空及文件名／进度／状态／操作。Rust保存任务快照，关闭重开窗口不重启任务；未决上传保留受控源副本并跨进程恢复，下载历史仅保留于当前进程。清空仅移除已结束记录，保留运行中和结果待核对的上传。
- 已登录且完成初始改密的用户都可查看、下载和使用，无需加入共享库。服务管理员可按用户名分别委派上传、删除、恢复，三个权限独立且对整个云文件库生效；新用户默认全部关闭。永久删除及权限调整仅服务管理员可执行，共享库角色不增加云文件管理权。
- 权限页复用现有用户名目录及更新接口，提供用户名／昵称搜索、状态和逐行保存；管理员固定全部权限。并发保存使用配置版本，冲突保留草稿；离开或关闭未保存页面先确认。无授权能力的旧Hub沿用固定管理员权限，并提示升级后才可配置授权。
- 服务管理员及有删除或恢复权限的用户可进入回收站。回收站显示上传／删除者及时间，历史缺失删除者显示“未知”；恢复支持单项和批量，永久删除必须逐文件输入完整名称。
- 编辑器“文件”工具提供“本机文件／云文件”。公共资料也可生成普通文件话术，再选择已有分类和标题；共享库编辑仍需要共享库编辑权。已有编辑窗口须先完成或关闭，避免覆盖草稿。
- 共享库话术直接引用云文件 ID，多库共用同一服务端本体。我的话术在保存时生成目标个人库自己的实际附件，无论是否开启同步；同一本机个人库再次选择同一来源时复用副本，退出后重新登录也无需重新下载已有可用个人副本。复用键包含服务器、用户名身份和文件 ID，不跨账号共享。
- 公共图片、文档、视频等保留原字节并作为文件附件；行内图片继续用现有图片工具。沿用每条9个文件及单文件128MB限制。
- 文件 ID 对应不可变内容，同名新上传产生新 ID，更新话术须明确替换附件。标题和实际附件名称分开。
- 未缓存时先下载，完成后重新触发投递。全素材检查、目标核验、发送锁、剪贴板保护和中断规则继续生效，不自动发送或重试已执行段。

## 存储、协议与生命周期

Hub 在共享 SQLite 中保存 `company_files`、目录版本及待清理记录，本体位于 `company-files/<ID>`。共享库 `assets.team_id` 及其原有清理规则保留。

公开协议增加 `CompanyFile`、`CompanyFiles` 和默认关闭的 `capabilities.companyFiles`、`capabilities.companyFilePermissions`；`User.companyFilePermissions`缺省为无委派授权。共享库快照增加默认空的 `companyAssetIds`，由服务端推导。普通话术仍使用原 `File(assetId,name)`。共享库下载接口在逐次授权后解析已保留的云文件引用，使现有支持共享库文件块的客户端可下载。

| 接口 | 用途 |
|---|---|
| `GET /api/company/files?q=&recycled=false` | 当前目录、搜索和目录版本；回收站向管理员及有删除／恢复授权的用户开放 |
| `GET /api/company/files/{id}` | 查询原上传任务结果及文件元数据 |
| `GET / PUT /api/company/files/{id}/content` | 下载／流式上传不可变本体 |
| `POST /api/company/files/{id}/recycle` | 删除（移入回收站），停止新引用 |
| `POST /api/company/files/{id}/restore` | 恢复同一条资料 |
| `DELETE /api/company/files/{id}` | 已回收且无保留引用时永久删除，需完整文件名确认 |
| `GET /api/users`、`PUT /api/users/{id}` | 服务管理员按用户名查询和修改云文件授权；普通账号资料更新不覆盖未提供的授权 |

上传先固化本机源副本和任务 ID，待核对任务独立于登录缓存保存，重启及重新登录后可以明确查询并继续。回执丢失先查询同一 ID，只有明确不存在才重新传输；已登记资料不能覆盖。正文选择使用明确的 ID 与位置类型，不能将云 ID 或 URL 当作本地路径。

现有`users`记录增加三个授权位、配置版本和上传授权版本。`UserWrite.companyFilePermissions`为可选更新对象，包含三个授权及`expectedVersion`；未提供时保持原授权。配置有变化时增加配置版本，仅上传授权变化时增加上传版本。上传请求携带`expectedUploadVersion`，Hub在开始及正式登记时逐次核验会话、权限和同一版本；撤权再授权仍拒绝此前的在途上传，删除／恢复授权变化不打断上传。复用授权SSE刷新界面和取消失效上传；撤回上传权限后仍可查询已登记结果。

目录变化通过 `company-files-version` SSE 通知。缓存按连接、账号和文件 ID 隔离，同一账号下多个共享库共用云文件缓存及下载锁，下载沿用全局两个许可。缓存按素材目录保存合法原文件名，长名称截短保留扩展名；退出、切号、停用和旧任务失效检查沿用现有账号规则，个人附件独立保留。上传只接受标准小写 UUID，避免 Windows 大小写别名覆盖既有本体；云文件与共享库素材禁止重复 ID，共享库引用的文件名须与云文件目录一致。

删除会移入回收站，保留本体和原话术引用；原话术编辑、话术回收还原及整库还原仍可用，新增引用被拒绝。永久删除与发布共用数据库锁和事务，检查所有活动共享库、已回收共享库和话术回收记录，不检查用户个人内容。永久删除保留最小 ID 删除标记，旧上传任务不能复活资料。文件删除失败保留待清理记录，启动时重试；共享库永久删除仅处理本库素材和引用。

个人副本会增加磁盘和下载流量成本，跨账号仍各自保存；删除云文件无法收回个人副本、另存文件或已发送内容。

## 导入导出与备份

统一 ZIP 版本2包含实际附件字节，云文件导出通过同一共享库素材解析取得本体；普通导入生成目标库独立附件，不重建云文件目录、用户名或权限。缺失附件、下载失败、取消或身份变化停止打包并保留原备份。

共享数据备份保存用户名授权和版本、云文件目录、删除者和回收状态及实际本体，排除用户个人内容及会话凭据。完整运维备份仍为停服保存整个数据目录，并按现有流程核对身份和同步世代。旧数据无损增加空云文件目录及缺省关闭的用户授权，不自动收录历史共享库附件。先升级 Hub，再更新客户端。

## 验证与发布边界

当前普通账号及root部署的实际结果以[验收记录](acceptance.md)顶部2026-10-14记录为准：前端111项、客户端Rust107项、模型3项、Hub Rust33项、发布脚本14项及Hub Python4项通过，双方格式、Clippy、TypeScript和构建通过。Windows隔离联调通过云文件19组、共享库18组、个人同步7组、导入导出14组；视频布局、纯图标操作、分页、进度和改名后的用户名列已复核。

公开Compose和默认Dockerfile使用正式Git依赖、单容器root及自动创建bind目录，实际容器7组通过，包含旧UID10001目录接入及两类备份恢复。旧Hub真实二进制3组兼容结果保留于验收历史，旧共享库客户端连接新Hub仍未实测。

本轮企业微信及Windows11安装矩阵全部通过，来源为负责人在本会话明确确认；系统DPI、多显示器、Windows10、真实局域网和HTTPS代理仍有环境缺口。本轮不替换用户安装或现有WSL部署。正式发布先Hub公开镜像，再Windows客户端，实际远端结果追加于验收记录；版本标签和既有资产不覆盖，客户端未代码签名。
